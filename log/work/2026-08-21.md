## [已完成] 2026-08-21 (追加2) — Startup Home 微調：hover gap + 診斷 modal 被蓋

### 需求與修改
1. **hover 選單與按鈕 gap 致滑鼠無法移動**
   - 根因：`.startup-new-menu { top: calc(100% + 6px) }` 造成按鈕與選單間 6px 空白，滑鼠移離按鈕即離開 hover zone → 選單消失
   - 修正：`ui/src/style.css` `.startup-new-menu` `top` 改為 `100%`（無 gap，滑鼠可連續移動）；視覺分離靠 box-shadow 維持
2. **檢查套件成功 (log: updateEnvironmentStatus received) 但 modal 未顯示**
   - 根因：`.modal-overlay { z-index: 1000 }` 遠低於 Startup Home inline `z-index: 10002` → 診斷視窗被 Startup Home 壓在底下，雖有 log 但肉眼不可見
   - 修正：`ui/src/style.css` 新增 `#diagnose-modal { z-index: 10050 }`（僅此視窗提高，高於 Startup Home；不影響其他 modal）

### 技術深挖 (Technical Deep Dive)
- **hover dropdown gap 常見陷阱**：`top` 與按鈕之間有間隙時，`:hover` 是往子選單的延續，pointer 離開父元素即失去 hover 狀態 → 下拉收回。常見解法為 gap=0（`top:100%`）或以偽元素/`padding` 橋接間隙
- **z-index 疊置**：Startup Home 特意設 `z-index:10002` 蓋住一般 `z-index:1000` 的 overlay。診斷按鈕在 Startup 內觸發的 overlay 必須局部覆蓋其 z-index；採 `#diagnose-modal` ID 特例（10050）最精準，避免全域調高影響 save-confirm/quick-pick
