## 技術深挖 (Technical Deep Dive)

### Tauri 指令註冊二階段流程
1. **定義 (Define)**：在 `src-tauri/permissions/commands.toml` 的 `commands.allow` 陣列加入指令名稱
2. **分配 (Assign)**：`src-tauri/capabilities/default.json` 引用 `"allow-all-commands"` identifier
3. 若未完成定義，指令在 Release Build 會被攔截

### `AppState.current_paths` 的作用
- `state.rs` 定義 `current_paths: Arc<Mutex<HashMap<String, PathBuf>>>`
- Key 是 window label，Value 是當前檔案路徑
- 在 `file.rs` 的 `open_file`、`save_file` 中設定
- 視窗關閉時在 `lib.rs` 的 `on_window_event` 中清除
- `find_latest_training_report` 利用此狀態取得 baseDir，無需前端傳入

### `open::that()` vs `vscode.env.openExternal()`
- `open::that()` 是 Rust crate `open` 提供的跨平台 API，直接呼叫系統預設瀏覽器
- `vscode.env.openExternal()` 是 VS Code Extension API，透過 VS Code 內部機制開啟
- 兩者功能相同，但 `open::that()` 對中文路徑處理較佳（Windows 上使用 ShellExecute）

### 技術深挖 (Technical Deep Dive)

#### TensorFlow 確定性運算
- `TF_DETERMINISTIC_OPS=1`：強制所有 op 使用確定性實作
- `TF_CUDNN_DETERMINISTIC=1`：強制 cuDNN 使用確定性演算法
- `tf.config.experimental.enable_op_determinism()`：TF 2.9+ 全域啟用確定性
- 這些設定確保相同輸入產生相同輸出，跨環境再現性

#### VSCode Terminal API 限制
- `onDidWriteTerminalData` 是 Proposed API，不穩定
- 改用 `child_process.spawn()` 直接執行，piped stdout 可靠地解析輸出
- 缺點：失去 VSCode 終端機的互動性（如 stdin 輸入），但訓練腳本不需要互動

#### sendText vs OutputChannel vs Pseudoterminal（重要修正歷程）
- **問題 1**：最初用 `terminal.sendText(text, false)` 顯示 stdout，但 `sendText` 會將文字當作命令發送到終端機，導致 `執行訓練命令:` 被 PowerShell 當作指令執行而報錯
- **問題 2**：改用 `OutputChannel` 雖然解決了命令執行問題，但 `OutputChannel` 不支援 ANSI 色碼，訓練進度條的色碼無法正確顯示
- **最終修正**：改用 `vscode.Pseudoterminal` + `vscode.window.createTerminal({ pty })` 建立虛擬終端機
  - `Pseudoterminal` 支援 ANSI 色碼顯示（與原終端機一致）
  - 透過 `writeEmitter.fire(text)` 寫入輸出，不會將內容當作命令執行
  - `close` 回調中終止 child process
  - `\n` 需轉換為 `\r\n`（終端機換行格式）

#### ANSI 色碼過濾
- ANSI 序列格式：`ESC [ ... letter`
- `strip_ansi_codes()` 用 peekable iterator 逐字元掃描，遇到 ESC 後消費整個序列
- 確保終端機輸出與 VSIX 版一致（VSCode 終端機原生處理色碼）
