## 追加（2026-09-04 第六輪）：int8 推論精度崩壞 — representative dataset 值域錯誤

### 根因
- 遠端路徑 `_local_convert_tflite.py` 的 `build_representative_dataset` 直接 yield `image_dataset_from_directory` 的原始像素（0~255），**沒有做訓練端 `Rescaling(1./255)` 的正規化**。
- converter 依 representative 統計 activation min/max → input scale 被估在 [0,255] 域，而模型實際以 [0,1] 訓練 → 推論時輸入等效放大 255 倍 → activation 溢出量化範圍 → int8 輸出近乎隨機；f32 不吃 quantization 參數所以正常。
- 本機訓練路徑（model_export.py 用 train_ds.take(100)，已含正規化）不受影響——bug 僅存在於「遠端訓練 → 本地轉 TFLite」路徑。
- 2026-08-31 驗證只確認「檔案產出 + UINT8」，未驗證 int8 精度，bug 一直埋著。

### 技術深挖 (Technical Deep Dive)
- **量化鐵律（新）**：representative dataset 的前處理必須與訓練 pipeline 完全一致（含 Rescaling、preprocess_input）。任何不一致都會直接毀掉 int8 精度，且轉換流程不會報錯——只能靠輸出比對發現。
- 修復：`build_representative_dataset` 加 `ds.map(lambda x, y: (tf.cast(x, tf.float32) / 255.0, y))`。
- 實測（本地 2 epochs 訓練 keras → 修復後轉換 → 60 張資料集影像比對）：int8 vs f32 argmax 一致率 96.7%（58/60）、平均 confidence 差 0.060、int8 準確率 81.7% vs f32 85.0%——正常量化損耗範圍。

- resources/dataset_manager/_local_convert_tflite.py：build_representative_dataset 補 1/255 正規化 + 鐵律註解
