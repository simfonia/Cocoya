## 修復：反向定位第二次點其它 code 未取消舊高亮 (2026-09-08 14:55)
- 症狀：第二次點到其它 code 行時，前一次的 code 高亮(.highlight-line)與積木選取框皆未取消。
- 根因（對照核心確診）：`BlockSvg.select(){ addSelect(); fireSelectedEvent(this) }` 只「加上」自己的選取框並 fire 事件，不會先 unselect 前一個積木（對稱取消由 Blockly FocusManager 驅動路徑負責）。直接 block.select() 繞過 focus → 多積木框疊加。而 code 高亮清除依賴「SELECTED→workspace listener→syncSelection」間接鏈，可能被 isInputActive 等中斷。
- 修法（renderer.js locateBlockByLineIndex）：
  1) 明確呼叫 this.syncSelection(blockId) —— syncSelection 開頭必然清除所有舊 .highlight-line 再高亮新範圍，保證第二次也清除，不依賴事件回饋。
  2) 積木側改用 focus 驅動的 Blockly.setSelected(block)（自動 unselect 舊框→addSelect 新框並 fire SELECTED；已確認公開 API blockly.js:22 / :110 / :596）；不要再直接 block.select()。
  3) fallback 依序 block.select() / ws.highlightBlock(blockId, true)。
- 驗證：node --check ✓、vite build ✓ (155ms)。實機再測：連點不同 code 行，前一次 code 高亮與積木框皆自動取消。
## 修復 v2：反向定位積木高亮累積 + 點空白不清除 (2026-09-08 15:25)
- 症狀：
  1) 換點其它 code 行時，舊積木(selection 框)仍高亮，一直累積到全部高亮；
  2) 點編輯區空白處，積木高亮不會消失。
- 根因（讀核心確診，非猜測）：Blockly 的選取/取消由 FocusManager.focusNode 驅動，依賴 DOM focus（document.activeElement、FocusableTreeTraverser）。在 webview(VS Code/Tauri) 下 focus 機制不穩定 → 反選新積木時舊積木不會被 unselect → 框累積；點空白原生「取消選取」也不作用。
- 修法（renderer.js，繞開 focus、手動管理視覺）：
  a) 新增 clearBlockHighlight(ws)：ws.highlightBlock()〔清空 highlightedBlocks 陣列〕＋ 對 ws.getAllBlocks(false) 每個 removeSelect()〔移除 .blocklySelected 框〕。addSelect/removeSelect 是 BlockSvg 公開方法(blockly.js:1066, 直接操作 pathObject.updateSelected)，不需 DOM focus。
  b) locateBlockByLineIndex：先 this.clearBlockHighlight(ws) 清全部積木框，再對目標 addSelect()〔唯一 keep〕＋ this.syncSelection(blockId)〔code 高亮〕。
  c) 新增 bindWorkspaceClickToClearHighlight()：綁 workspace.getParentSvg().pointerdown，target 非積木(無 [data-id] 祖先/allWidgetDiv/dropdownDiv) 即 clearBlockHighlight + syncSelection(null)。有 data-cocoya-clear-bound 去重標記。
