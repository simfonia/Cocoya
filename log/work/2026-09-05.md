### 技術深挖 (Technical Deep Dive)
- **把手不能放在 `#terminalArea` 內部**：`.collapsed` 有 `opacity:0; pointer-events:none` 且 `overflow:hidden`，內部把手會被隱藏/裁切（2026-05-03 `#code-toggle` 曾踩過同類坑，該案例是靠 collapsed 時保留把手可見解決；terminal 版直接放外部作兄弟節點更乾淨）。`#blocklyArea` 為 `position:relative` flex column，把手 absolute 錨 `bottom`，由 JS `syncTerminalToggle()` 同步 = 終端機 offsetHeight，展開時貼在終端機上緣、收合時貼底。
- **inline height 與收合衝突**：拖曳後 `panel.style.height` 為 inline style，會蓋過 `.collapsed { height:0 }` → 收合失效；解法為 `height:0 !important`，重新展開時 inline height 自動恢復使用者偏好尺寸。
- **拖曳沿用 `#panel-resizer` 慣例**：`requestAnimationFrame` 節流、`#resizer-overlay`（fixed 全螢幕）擋 mouseover 干擾（新增 `body.resizing-terminal` 觸發）、mouseup 後 `Blockly.svgResize()` + `window resize` 事件讓畫布重新適配。
- **字體記憶**：`localStorage` key `cocoya_terminal_fontsize` / `cocoya_code_fontsize`，init 時還原套用。

## 追記：把手位置 Bug 修正（同日）
- **症狀**：把手位置顛倒——展開時在面板最下方、收合時在上方。
- **根因**：`syncTerminalToggle()` 在 `toggleTerminal()` 切換 class 後立即讀 `panel.offsetHeight`，但 `#terminalArea` 高度有 0.3s transition，當下量到的是**舊值** → bottom 套到錯誤高度。
- **修正（依使用者需求改為「面板上緣水平置中」）**：捨棄 JS 同步位置的方案，改把 `#terminal-toggle` 移入永遠存在於版面中的 `#terminal-resizer`（加 `position:relative`），絕對定位 `left:50%; translateX(-50%); bottom:6px`（40×16 橫向膠囊、圓角朝上），位置完全由 CSS 錨定，收合/展開皆正確。`syncTerminalToggle()` 只負責箭頭方向；`resizer.onmousedown` 加 `e.target.closest('#terminal-toggle')` 防止點把手誤觸拖曳。
- **箭頭方向**：使用者確認原語意正確（收合=▲、展開=▼），已改回。
- 驗證：`node --check` + `npx vite build` 全綠。

## 追記：codeHeader 關閉鈕 hover 無變色（同日）
- 根因：`#btn-close-code` 的「×」是純文字 `<span>`，既有 hover 規則只覆蓋 `.toolbar-btn` 背景與 `img`（`filter` 轉品牌色），文字色不變；且淺色主題 hover 底色 `#f0f0f0` 與 `--code-header-bg #f3f3f3` 過近，肉眼幾乎無感。
- 修正：style.css 新增 `#btn-close-code:hover span { color: #FE2F89; }`（深色主題 hover 底 `#3e3e3e` 由 cocoya_dark.js 既有規則處理，文字同樣變粉）。
- 驗證：`npx vite build` 通過。
