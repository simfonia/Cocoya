技術深挖 (Technical Deep Dive)

1. Pybricks vs 原廠韌體選型

比較後選擇 Pybricks 的原因：

  • Pybricks 提供高層次 API（motor.run(), sensor.color()），適合初學者
  • 原廠 MicroPython API 較底層，需手動處理許多細節
  • Pybricks 支援多 Hub（SPIKE、Technic、BOOST、City、Robot Inventor）
  • Blockly 積木可直接映射到 Pybricks API

2. deploy_mcu.py 重構決策

原始 deploy_mcu.py 僅 268 行，但 Pybricks 上傳協定與 MicroPython Raw REPL 不同：

  • MicroPython：Ctrl-C 中斷 → Ctrl-A 進入 Raw REPL → 送出程式碼 → Ctrl-D 執行
  • Pybricks：Ctrl-C 中斷 → 直接送出程式碼 → 換行觸發執行

若將兩者塞在同一個檔案，會增加條件分支複雜度。因此採用工廠模式分離。

3. Toolbox 多層分類設計

Blockly 原生支援巢狀 <category> 元素，可實現可收合的樹狀結構：

<category name="Lego SPIKE" colour="#FF6680">
    <category name="馬達控制" colour="#FF6680">
        <block type="spike_motor_run"></block>
    </category>
    <category name="感測器" colour="#FF6680">
        <category name="顏色感測器" colour="#FF6680">
            <block type="spike_color_detect"></block>
        </category>
    </category>
</category>
