## Dataset Manager UI 修改

### 需求
1. **訊息區位置與自動清除**：原先 `#dataset-import-status` 位於左欄 `.dataset-source-panel`，標註模式會隱藏該面板導致訊息看不到；且從不會自動清除。移至「頂部中央」、所有模式下皆可見，並於 5 秒後自動清除。

### 根因
- (1) `#dataset-import-status` 位在 source 面板內且無自動清除。
- (2) `renderAnnotationControls()` 的 bbox 新增/編輯/刪除類別、`refreshDynamicPanels()` 的 `onLabelChange` 新增標籤都未觸發 `refreshPreview()`。
- (3) 匯入按鈕插在模式與名稱/描述之間，流程較不順。

### 技術深挖 (Technical Deep Dive)
- **集中式訊息 vs 全域廣播**：沿用單一 `statusMessageTimer` 全域計時器變數，`showStatusMessage()` 顯示時先 `clearTimeout` 再重設，確保「上傳進度」這類連續更新不會被前一筆的計時器提前隱藏，且最後一筆起算 5 秒後正確清除。
- **function 提升**：`showStatusMessage` 為模組級 function 宣告，雖定義在檔案中段（原 `getExportStatusElement()` 位置），因 hoisting 可在先前定義的 `applyLoadedProgress` / `handleFileImport` 等呼叫，無需調整順序。
- **refreshPreview 防抖**：`refreshPreview()` 內部 300ms 防抖後同步 `state.spec` 並寫入 `#dataset-json-preview`，故標籤異動後約 0.3 秒內預覽即時反映。

## Dataset Manager UI 修改（二）：名稱對齊方案 A + 訊息欄置中/時長

### 需求
1. 資料集名稱欄位：重選來源資料夾時名稱未自動更新，有靜默覆寫錯誤 namespace（例如 D1/dataset.json）的風險。
2. 訊息欄文字未垂直置中、預設 5 秒消失太快。

### 決策（方案 A：來源變更顯式確認）
經 4 情境評估（新專案／多 dataset 碰撞／另存引導／table 位置）後捨棄「一律同步」：
- 一律同步無法解決 basename 碰撞（A/data 與 B/data 同名皆變 data→覆寫同一 namespace）與「開舊進度改存另一 dataset」的改名混淆。
- 改採來源變更時顯式 confirm：確認=更新名稱、取消=維持名稱並提示可能覆寫；同名不同來源則警告。

### 情境評估結論
1. 新 dataset（資料夾未建立）：無問題——後端 VSIX mkdirSync(recursive)、Tauri create_dir_all 均自動建 dataset/<名稱>/。
2. 同一 xml 多 dataset：以名稱 namespace 區隔；basename 可能碰撞（A/data vs B/data）——需防寫。
3. 開舊進度改存另一 dataset：由 confirm 讓使用者決定，並引導自行複製來源再匯入。
4. table 型 CSV 不在 <專案根>/dataset/<名稱> 下：無問題——rows 直接內嵌於 spec.data_source.samples，來源位置不影響儲存。

### 修 bug：%1/%2 佔位符未取代
測試發現 `SOURCE_KEPT_STATUS`（訊息框）與 `SOURCE_RENAME_CONFIRM`/`SOURCE_COLLISION_CONFIRM`（confirm）的 %1/%2 殘留未取代。
根因：`t()` 是「多引數+全域 regex」取代（i18n.js L23-27）；但先前用 `t('KEY', fallback).replace('%1', v)` 鏈式取代，而字串 `.replace('%1', s)` 只替換第一個出現處，導致重複出現的名稱/路徑（如 dataset/%1/）殘留字面 %1/%2。
修正：改為 `t('KEY', fallback, value1, value2)` 傳引數，由 t() 以全域 regex 取代所有 %1/%2。
(此對既有單次佔位符訊息無影響，仍可保留鏈式 replace。)
