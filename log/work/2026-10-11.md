## Editor 純文字模式（D-2 實機回報第二輪：#1 行號間距、#9 Tab 語意）

### #1 行號與第一個字緊貼 → 根因是 `box-sizing`
`.editor-gutter .ln` 原本是 `display:block; width:100%; text-align:right; padding-right:10px`，
**沒有宣告 `box-sizing`** → 沿用預設 `content-box`。在 content-box 下 `width:100%` 指的是
**內容區**寬度（= 父層 36px），`padding-right:10px` 被排到這 36px **之外**，
再被父層 `.editor-gutter` 的 `overflow:hidden` 裁掉。
結果 `text-align:right` 把行號的右緣對到 x=36px —— 恰好就是文字層
`padding-left:36px` 的起點 → **行號與第一個字零間距緊貼**，而那 10px 留白從未生效。

修法：`.ln` 補 `box-sizing: border-box`，此時 36px 含 padding，右緣收到 x=26px，
10px 留白如預期落在行號與文字之間。**只改 padding 值是不會修好的**（原本就設了 10px 卻被裁掉）。

### #9 縮排標籤依模式切換語意
實驗室中該欄位實際是「按 Tab 會插入幾格」，標「縮排：」語意不準；退出後又該回到
「產生碼的縮排寬」。實作：

**故一併刪除，符合專案「不做相容層」決策**（見 AGENTS.md task type 鐵律段落）。

## 階段 B：資料接線（本移植真正的差異點）

### 事實核查：`python-log` 是**單一事件通道**
序列埠資料（`monitor.rs`）、deploy 輸出（`deploy.rs`）、PC Python stdout（`python.rs`）、
訓練日誌、韌體燒錄（`firmware.rs`）**全部** emit 同一個 `python-log` 事件名，
事件 payload **不帶來源**。計畫 §3 原假設「在 `bridge/tauri/serial.js` 的序列埠資料路徑加 hook」
在 Cocoya 不成立 —— 該檔只有 invoke 端，**資料根本不過那裡**。

**判據改用 `serial-monitor-state` 的 `active`**（Rust 已用 generation/revision 權威管理）：
在 `tauri.js` 的 `python-log` listener 內以 `_serialMonitorActive` 閘門，只在真的持有序列埠
session 時餵給 plot。訓練／燒錄／PC 執行期間 monitor 已由 `stop_python` 釋放 → 不會誤食
（計畫 §5 列的「誤食訓練日誌」風險由結構本身排除，不靠命名猜測）。

### 逐行拆解（不拆會整批靜默消失）
`stream.rs::forward_stream_with_controls` 以 **30ms 時間窗聚合**，一個 payload 可能含多行。
而 `parseLine` 只處理單行（`
` 留在欄位裡 → 整行判為垃圾行）。故餵入前必須
`split('\n')`。高頻輸出時這個疏漏會讓**整批資料無聲消失**且畫面毫無錯誤。

### 適配層（刻意收斂成最小介面）
Cocoya 沒有 `CocoyaSerialMonitor`／`CocoyaTerminalPanel` 兩個 CodeBridge 物件，改以適配器提供
`plot-panel.js` 真正需要的三個欄位，**避免 plot 模組反向依賴 UI 層內部欄位命名**：
- `monitor()` → 讀 `CocoyaUI._serialMonitorConnected`／`_serialMonitorActive`
- `terminalPanel()` → 就地操作 `#terminalArea.style.height`（`null` = 移除 inline 回 CSS 預設）
- `text()` → 改讀 `Blockly.Msg`（Cocoya 的 i18n SSOT，無全域 `getI18n()`）
- `ensureSerialMonitor()` → **觸發 `#btn-serial-monitor` 的 onclick**，不複製 invoke 參數組裝
  （port／pythonPath／rawDump 的決定權在 `base.js`，複製一份必然漂移）

### 兩處語意修正（非照抄）
1. `openPlot` 的「要不要代開監看」判據由 `getState().connected` 改 `isActive()`：
   `connected=false` 的時機包含「active 但正在等重連」，原判據會把好 session 停掉重開
   （白等一次 Rust 的 400ms 冷卻）。
2. `init()` **不再訂閱 serial monitor**（Cocoya 無可訂閱物件），只負責畫面與控制項就緒，
   資料到達時才惰性建立 store。
3. HEX 判斷保留但恆 false：Cocoya 的 Serial Raw Dump 是**寫檔**（`<ProjectRoot>/raw_dump.log`），
   不是把終端機顯示切成 HEX —— 本專案沒有「HEX 模式」這個語意。

## 階段 D：測試與守門
新增 2 檔 **37 測**：`plot_parse.test.mjs`（16）、`plot_store.test.mjs`（21）。

### 踩坑①：vm 跨 realm 讓 deepStrictEqual 全數假失敗
用 `vm.runInNewContext` 載入 IIFE 時，回傳的陣列／RegExp 屬於另一個 realm，原型不同 →
`deepStrictEqual` 以「Values have same structure but are not reference-equal」拒收，
**正確的實作看起來全部失敗**（首輪 7/15 紅）。改用 `runInThisContext`（載入期間掛 `window`、
結束還原）。

### 踩坑②：三個「失敗」其實是我的預期錯，實作是對的
逐一查證原始碼後**改測試不改實作**，並把真實語意寫進註解：
1. `sampleCount` 數的是**行數**（push 次數）而非點數 —— 一批兩點只算一次取樣，
   這也讓 UI 樣本數對應 MCU 的 print 次數。
2. Y 軸**下限恆含 0**（`computeRange` 的 min 初始 0 且只單向擴張）—— 感測資料的 0
   通常是物理基準，排除它會讓使用者誤判絕對大小；負值仍能把下限拉下去。
3. 下抽樣的 orphan **只在「整格全斷線」時**保留 null；混合格只輸出 min/max 包絡
   （尖峰與整體輪廓優先）。這是已知行為，非缺陷。

### 踩坑③：守門判據過寬（假安全感的反向）
首版斷言「來源不得含 `CodeBridge` 字串」，結果被我自己寫的 provenance 註解觸發假紅。
收斂為識別字層級：禁 `CodeBridgePlot` 命名空間（`ensureCore` 會取不到）與
`window.CodeBridge*` 全域參考（執行期 TypeError）—— 註解記錄來源是有價值的，不該為綠燈抹掉。

### 變異測試（確認守門真的有效）
把 `plot-panel.js`／`plot-render.js` 的載入順序對調 → **立刻轉紅**（pass 15 / fail 1）。
⚠️ 過程中 PowerShell 的 `-Replace` 因字串未命中而**靜默沒變異**（測試仍全綠），一度誤判
「守門無效」；改用 Node 腳本並印出 `mutated: true` 確認真的改到才重跑。
教訓：**變異腳本必須回報「我到底改到了沒有」**，否則會把「mutation 沒生效」誤讀成「守門沒效」。

## Plotter 開關按鈕改 icon-only（wave-sine.png）＋ 三處冗餘狀態編碼（2026-10-11）

使用者要求：按鈕改用 `wave-sine.png`，並要有狀態切換。

### 改動
- `index.html`：`#btn-plotter` 由**文字鈕**改為 **icon-only**（內含 `<img src="src/icons/wave-sine.png">`），
  與終端機 header 相鄰的 terminal icon 鈕（copy／font-size／pause／clear／close）同尺寸同樣式。
  移除了 `serial-toggle-btn` class（那是給有邊框的文字鈕用的，icon 鈕用了會多一圈框）。
- `style.css`：由 **「品牌粉底 + `filter: brightness(0) invert(1)`」 改為「透明底 + 品牌粉 `inset` ring + img `opacity: 1`」**：
  因使用者把 `wave-sine.png` 改成品牌粉（解析畫素確認 RGB = 254,47,137、與專案主色同值）：
  ① 沿用粉底 + 反白會把粉 icon 轉成**青色**、品牌識別消失；
  ② 粉 icon 落粉底對比不足，圖示「融進」底色。故改 **透明底 + 粉 ring**：
  `inset 0 0 0 1px`（不用 `border` 避開尺寸 4→5px）；未啟用 `opacity 0.8` 壓在最深 header
  `#252526` 上（實測 **4.36:1**）；啟用**不加深底色**（粉 on `#3e3e42` 僅 **3.03:1**，不及 AA 4.5:1）
  —— 用 ring + opacity 三處編碼表達狀態。

### 2026-10-11 使用者改 png（深色 → 品牌粉）後的續補
- `wave-sine.png` 實測為**純黑**（RGB 0,0,0）＋ alpha 漸層、不透明 15.2%。
  改粉後，`filter: brightness(0) invert(1)` 需刪除（會把粉轉青）。
- **變異測試**：原 `style.css` 的 `filter: brightness(0) invert(1)` 版本 → 假紅；
  調整為「透明底 + 粉 ring」後 525/525 綠。

- `plot-panel.js` `syncControls()`：**移除 `toggle.textContent = label`**，只寫 `title`。

### ⚠️ 關鍵陷阱：icon-only 按鈕絕不可寫 textContent
`textContent = label` 會把 `<img>` 子節點整個替換成文字。症狀是「按鈕從此變成空白框」，
而**程式碼看起來完全正常、沒有任何錯誤訊息** —— 因為 init 之後 syncControls 每次都會重跑一次，
連「第一次正常、之後壞掉」都觀察不到，是開工就壞。

### 狀態因此改由三處冗餘編碼表達（不單靠顏色）
1. `.is-active` 底色（品牌色）
2. img `opacity`：未啟用 0.8（HTML inline）／啟用 1
3. `title` 文案 `PLOT_OPEN` ↔ `PLOT_CLOSE` ＋ `aria-pressed`（螢幕閱讀器）

### 新增 2 支守門（共 18 測）
1. `#btn-plotter` 必須 icon-only：子節點內容不得有 `%{BKY_}` 殘留（title 用佔位符是**合法**的，
   只有寫在 `>...<` 之間才會變成看得見的字）＋第一個子節點必須是 `<img>` ＋必須是 wave-sine.png。
2. `syncControls` 的 btn-plotter 區段（**剝除行內註解後**）不得出現 `textContent`。

### 變異測試
① 把 `textContent = label` 加回 → **報紅**。② 把 icon 換回 `%{BKY_PLOT_OPEN}` 文字 → **報紅**。
兩者皆確認守門有效（還原後 18/18 綠）。

### 兩個測試自身的坑（都記錄，重寫時會再遇到）
- 判據不可用「開標籤不得含 `%{BKY_}`」：`title="%{BKY_PLOT_OPEN}"` 是 icon 鈕的正確用法，
  那樣寫會把自己的正確實作判成假紅。
- 斷言「剝除註解後不得含 textContent」時**必須真的剝**：說明為何不可寫的註解本身就含該字串。
- 切片要從 `tagEnd + 1` 起算（`tagEnd` 指向前一個 `>`）；含著 `>` 會讓 `/^\s*<img/` 永不匹配，
  而那不是實作的錯 —— 我一度據此懷疑 HTML 寫錯了。
