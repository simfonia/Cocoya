## 技術深挖 (Technical Deep Dive)

### 回歸模型設計
- **輸出層**：`Dense(4, activation='sigmoid')` — 4 個值 [cx, cy, w, h]，sigmoid 限制在 0~1
- **損失函數**：MSE (Mean Squared Error) — 回歸任務標準選擇
- **輔助指標**：MAE (Mean Absolute Error) — 直觀理解預測偏差
- **與分類的差異**：分類用 softmax + categorical_crossentropy，回歸用 sigmoid + MSE

### YOLO 座標系統
- **Dataset Manager 內部**：`bbox: [x, y, w, h]`（左上角 + 寬高，比例座標 0~1）
- **YOLO 格式**：`class_id cx cy w h`（中心點 + 寬高，歸一化座標）
- **轉換公式**：`cx = x + w/2, cy = y + h/2`
- **推論端逆轉換**：`x1 = cx - w/2, y1 = cy - h/2, x2 = cx + w/2, y2 = cy + h/2`

### TFLite int8 量化相容性
- 回歸模型的 int8 量化需要確認輸出精度
- sigmoid 輸出在 0~1 範圍，int8 量化後精度約 1/255 ≈ 0.004
- 對於 bbox 座標（0~1 比例），此精度足夠（224px 影像上約 ±1px）

### Sidecar 匯出 YOLO 的架構優勢
- VSIX 和 Tauri 都透過 sidecar 匯出，修改一處即可雙平台同步
- sidecar 在打包 ZIP 前讀取 `dataset.json`，將 annotations 寫入 `labels/`
- 不需要修改 `datasetOps.ts`（VSIX）或 `dataset.rs`（Tauri）

### bbox_center 積木的 lambda 技巧
- 產生器使用 Python lambda 避免產生額外的函式定義
- `(lambda b: ((b[0]+b[2])/2, (b[1]+b[3])/2))(bbox)` — 內聯計算中心點
- 這樣可以保持積木的純表達式特性，不需要在 `definitions_` 中注入函式

## 修正：04_MCU_tracking.xml 積木值錯誤

### 問題
`04_MCU_tracking.xml` 使用了不存在的積木選項值：
- `py_math_arithmetic` 的 `OP=MULTIPLY`（實際選項是 `*`）
- `py_math_single` 的 `OP=ROUND`（實際沒有此選項，`py_math_round` 是獨立積木）

### 修正
- `py_math_arithmetic` 的 `OP` 改為 `*`
- `py_math_single` 改為 `py_math_round` 積木

### 教訓
- 建立 XML 範例時，必須確認積木的實際選項值（dropdown options）
- 數學運算符號使用 `+`, `-`, `*`, `/`, `%`, `**` 而非英文名稱
- `round()` 是獨立積木 `py_math_round`，不是 `py_math_single` 的選項
