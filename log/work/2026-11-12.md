## 技術深挖 (Technical Deep Dive)

### 1. 錯誤根因：`FileNotFoundError: Labels: model/lines\lines_labels.txt`

`_ModelInference.__init__`（`ai_inference_generators.js` 第 198-206 行）不論 `task_type` 為何，都強制執行：

```python
lbl = os.path.join(d, os.path.basename(d) + "_labels.txt")
if not os.path.exists(lbl): raise FileNotFoundError("Labels: " + lbl)
```

範例 `model/lines/` 僅有 `lines_f32.tflite`，**沒有 `lines_labels.txt`**，導致推論初始化即失敗，未進入 `_follow_line`。

### 2. 為什麼 `line_following` 不需要 labels

依 AGENTS.md「訓練集切分鐵律」，`line_following` **無類別欄位**（`class_id` 恆 0），屬**回歸型**任務。`_follow_line`（第 247-279 行）完全未參考 `self.ls`；僅 `image_classification` / `object_detection` 需要標籤對照表。

### 3. 修改：條件式 labels 守門

將 `if not os.path.exists(lbl)` 改為僅對分類/偵測強制：

```python
# 僅分類/偵測任務需要類別標籤；循線/表格型為回歸或預留，不依賴 labels.txt
if task_type in ("image_classification", "object_detection") and not os.path.exists(lbl):
    raise FileNotFoundError("Labels: " + lbl)
...
self.ls = [line.strip() for line in open(lbl)] if os.path.exists(lbl) else []
```

保護既有行為：分類/偵測維持強制檢查；`_classify` / `_detect` 原有防護（`cid < len(self.ls)` / `self.ls[0] if self.ls else "object"）不動。

### 4. 箭頭看不見的第二個原因：歸一化座標 vs 像素座標

`line_generator.py` 第 254-257 行與 `line_following_train.py` 註解皆說明模型輸出為**歸一化比例座標 (0~1)**。`cv2.arrowedLine` 需要像素座標，故需 `int(x*w)` / `int(y*h)` 轉換。

### 5. 翻轉順序問題

原本順序 `read → predict(未翻轉) → flip(顯示) → 畫箭頭` 會造成：
- 模型輸入與顯示畫面不一致（訓練資料無翻轉，推論應用原始幀）
- 箭頭畫在已鏡像畫面上，座標與 `result.line` 不對應

修正為 `read → predict → 畫箭頭 → show`，**不翻轉**，推論與顯示同幀，座標系一致。
