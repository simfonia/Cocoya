### 已確認設計決策
1. **範圍**：Windows Tauri 多視窗；VSIX 不實作 Hub 或多視窗交接，POSIX 延後。只有改動共用 Python deployer／Blockly generator 時才做必要回歸。
2. **Hub 啟動**：PC Serial 積木自動啟動或加入該 port Hub，不依賴先上傳或先開監看。
3. **讀寫租約**：多個讀取／monitor subscriber 可共存；每個實體 port 同時間只允許一個 writer lease。寫入衝突明確拒絕並提示關閉占用視窗／序列埠程式後再試，不等待無限期、不靜默搶占、不殺其他程序。
4. **上傳交接**：部署先取得 Hub exclusive-port lease，Hub 安全暫停 client 並釋放實體 COM 後才部署；交接失敗時回報明確占用提示。部署完成後依仍存活的工作階段恢復 Hub/client。
5. **輸出隔離**：Hub 可在資料層 fan-out RX，但不把資料全域廣播至 UI terminal。MCU RX 只顯示於訂閱該 port 的 Tauri 視窗（`emit_to`）；PC proxy RX 只交給相應 Python 程式讀取；該程式 stdout 僅回到它所屬視窗。A 的 MCU 感測資料與 B 的 PC 程式 print 不串台；B 若自行讀取資料並 `print()`，則按程式行為顯示於 B。
6. **狀態與重連**：按鈕 active 代表本視窗 monitor session 存在，不代表 COM 已連線。拔除後維持 session 並無期限重試；插回同一 COM 名稱可恢復。COM 名稱改變時第一版提示重新選埠，不承諾自動追蹤。

1. **Rust monitor registry 與 generation**：`AppState.serial_monitor_registry` 追蹤每視窗 monitor/deploy child、port、active/connected、generation/revision；舊程序的延遲 marker/EOF 不得改寫新 generation。Focus handoff suspend 保留使用者 monitor intent、標示 disconnected，並使舊 reader callback 失效。
