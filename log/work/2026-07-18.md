## 今日異動

### [Bugfix] Tauri 版 Dataset Manager Webcam 掃描修復

**問題**：Tauri 版啟動 Dataset Manager 進入 Image Live 模式後，按下「重新掃描攝影機」無法列出 webcam 清單，程式卡住沒有回傳。

**原因**：`ui/src/bridge/tauri.js` 中所有 dataset 相關指令（`datasetListCameras`、`datasetStartCamera`、`datasetStopCamera`、`datasetCaptureImage`）都只透過 `_dispatchToFrontend` 發回前端，完全沒有啟動 Python sidecar 進程，導致 sidecar 根本沒被執行。

**對比**：VSIX 版運作正常，因為 VSIX 透過 `sidecarManager.ts` 啟動 Python `dataset_sidecar.py`，透過 stdin/stdout JSON 通訊。

#### Bug Fix 歷程

**第一次修正**：`sidecar_send` 使用 `BufReader` 逐行讀取 → 但 `BufReader` 預先緩衝導致 event 被吃掉，狀態不同步。

**第二次修正**：改用逐 byte 讀取 + 持續讀取 stdout 直到找到匹配 `requestId` 的 response，不匹配的行（event）透過 `window.emit("sidecar-event")` 發送到前端。

**第三次修正**：`datasetStopCamera` 的 callback 原本傳 `success: true`（停止成功），但 `sampler.js` 把 `success: true` 解讀為「攝影機正在執行」，導致按鈕卡在「停止攝影機」無法再次啟動 → 改為直接傳 `success: false`。

#### 技術深挖 (Technical Deep Dive)

**sidecar 通訊設計**：
- Tauri 端維護 `SidecarProcess` 封裝 child 進程的 stdin/stdout handle
- `sidecar_send` 是同步 request/response 模式：寫入 stdin 一行 JSON，持續讀取 stdout 直到找到匹配 `requestId` 的 response
- sidecar 背景主動推送的 event（如 `cameraStatus`）會被讀取並透過 `window.emit("sidecar-event")` 轉發到前端
- 前端 `_handleDatasetCommand` 會自動檢測 sidecar 是否活著，若未啟動則自動 `start_sidecar`

**逐 byte 讀取 vs BufReader**：
- `BufReader::read_line()` 會內部緩衝最多 8KB 資料，導致 event 被 buffer 吃掉
- 逐 byte `read()` 雖然較慢，但確保每一行都能被正確解析和分派
- 每次 `sidecar_send` 完成後 stdout 位置會停留在 response 行之後，下一次呼叫可以繼續讀取
