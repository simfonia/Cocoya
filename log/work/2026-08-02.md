## 技術深挖 (Technical Deep Dive)

### 參數傳遞鏈
`EXPORT_MODEL` 勾選框 → `train_model(export_model=...)` → `--export_model` CLI 旗標 → `classifier_train.py` 的 `args.export_model` → `export_model_enabled` 布林值 → 控制 TFLite 產出

### 向後相容性
- `--export_model` 有預設值 `false`，舊的呼叫（未傳此參數）仍可正常運作
- 產生器 `train_model()` 函式簽名加入 `export_model` 參數，但所有呼叫點都已同步更新
- 未勾選時仍產出曲線圖/歷史/報告，確保使用者能觀察訓練結果

### FieldCheckbox 字串判斷陷阱（重要修正）
- **問題**：Blockly 的 `FieldCheckbox.getValue()` 回傳字串 `"TRUE"`/`"FALSE"`，不是布林值
- 原本寫 `exportModel ? 'True' : 'False'`，字串 `"FALSE"` 是 truthy，永遠判斷為 `True`
- 導致「產生模型」預設未勾選，但產生的程式碼卻是 `export_model=True`
- **修正**：改用 `exportModel === 'TRUE' ? 'True' : 'False'` 精確比較字串
- **連帶修正**：`augmentation` 和 `fineTune` 也有相同 bug，一併修正為 `=== 'TRUE'` 比較

### 產出檔案列表誤列舊檔（重要修正）
- **問題**：未勾選「產生模型」時，`os.listdir(args.output_dir)` 會列出目錄中所有檔案（包括之前訓練留下的舊模型檔），造成報告誤導
- **修正**：`classifier_train.py` 的「列出產出檔案」區塊改為條件式：
  - `export_model_enabled=True`：列出所有產出檔案
  - `export_model_enabled=False`：只列出本次產出的結果檔案（`_training_curve.png`、`_training_history.json`、`_training_report.html`），並提示「未勾選「產生模型」，未產出 Keras/TFLite/labels 檔案」

### VSIX 終端機訓練後自動刪除（重要修正）
- **問題**：訓練完畢後 VSIX 的終端機自動刪除，看不到任何歷史過程
- **根本原因**：`envOps.ts` 的 Pseudoterminal `child.on('close')` 中呼叫 `closeEmitter.fire()`，觸發 `onDidClose` 事件導致 VSCode 自動關閉終端機
- **修正**：移除 `closeEmitter.fire()`，改為輸出「程式執行結束」提示，讓終端機保持開啟供使用者回顧完整輸出歷史
- 使用者可透過「停止」按鈕（`handleStopCode`）手動關閉終端機

## 模型輸出格式選單 + 推論積木模型類型選擇

### 需求
1. 將「產生模型」勾選框整合為「模型輸出」下拉選單，預設「無」
2. 推論積木加入「模型類型」下拉選單，可自訂使用哪個模型檔
3. 修正推論積木 glob 搜尋順序不保證的 bug

### 修改內容

#### 1. 積木定義（`ai_inference_blocks.js`）
- **訓練積木**：`EXPORT_MODEL` 勾選框 → `MODEL_OUTPUT` 下拉選單
  - 選項：無 / 量化 TFLite (int8) / Float32 TFLite / Keras / 量化 + Float32 / 全部
  - 預設「無」（僅觀察訓練結果）
- **推論積木**：加入 `MODEL_TYPE` 下拉選單
  - 選項：自動 / 量化 (int8) / Float32
  - 預設「自動」（優先 int8）

#### 2. 產生器（`ai_inference_generators.js`）
- **訓練產生器**：`export_model` → `model_output` 參數，`--export_model` → `--model_output` 旗標
- **推論產生器**：
  - `_ModelInference.__init__` 加入 `model_type` 參數
  - 修正 glob 搜尋邏輯：根據 `model_type` 篩選
    - `int8`：選擇不含 `_f32` 的 `.tflite`
    - `f32`：選擇含 `_f32` 的 `.tflite`
    - `auto`：優先選擇不含 `_f32` 的 `.tflite`

#### 3. 訓練腳本（`classifier_train.py`）
- `--export_model` → `--model_output` 參數
- 根據 `model_output` 值選擇性產出：
  - `none`：跳過所有模型檔案
  - `int8`：僅量化 TFLite + labels.txt
  - `f32`：僅 Float32 TFLite + labels.txt
  - `keras`：僅 Keras + labels.txt
  - `int8+f32`：兩種 TFLite + labels.txt
  - `all`：全部 + labels.txt
- 永遠產生 labels.txt（當 model_output != none 時）

#### 4. i18n（`zh-hant.js` + `en.js`）
- `AI_TRAIN_FIELD_MODEL_OUTPUT` / `AI_TRAIN_OUTPUT_*`
- `AI_INFERENCE_FIELD_MODEL_TYPE` / `AI_INFERENCE_TYPE_*`

### 行為
| 模型輸出 | 產出檔案 |
|---------|---------|
| 無（預設） | 曲線圖 + 歷史 + 報告 |
| 量化 TFLite (int8) | `.tflite` + `labels.txt` + 曲線圖/歷史/報告 |
| Float32 TFLite | `_f32.tflite` + `labels.txt` + 曲線圖/歷史/報告 |
| Keras | `.keras` + `labels.txt` + 曲線圖/歷史/報告 |
| 量化 + Float32 | 兩種 TFLite + `labels.txt` + 曲線圖/歷史/報告 |
| 全部 | Keras + 兩種 TFLite + `labels.txt` + 曲線圖/歷史/報告 |

### 推論積木模型類型
| 模型類型 | 行為 |
|---------|------|
| 自動（預設） | 優先選擇 int8，找不到才用 f32 |
| 量化 (int8) | 選擇不含 `_f32` 的 `.tflite` |
| Float32 | 選擇含 `_f32` 的 `.tflite` |
