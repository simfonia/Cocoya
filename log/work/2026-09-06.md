## 任務：語系切換對齊主題切換——保留編輯區積木

### 需求
目前主題切換可以即時更換而不影響已存在編輯區的積木（透過 `snapshotWorkspaceForReload` + `reloadWebview` 機制），但語系切換會全部清除。需對齊兩者行為。

### 討論決策
- **根因**：`theme_manager.js setMode()` 有先呼叫 `snapshotWorkspaceForReload()` 才 `reloadWebview`，但語系切換的兩個 handler（工具列 `ui/src/ui/base.js` 與首頁 `ui/src/app/persistence.js`）直接 `reloadWebview` 未快照 → workspace 記憶體內容在 reload 時遺失。

### 技術深挖 (Technical Deep Dive)
- **快照機制**：`persistence.js` 的 `snapshotWorkspaceForReload()` 將 workspace 轉為 XML 並以 `sessionStorage.setItem(SNAPSHOT_KEY, ...)` 儲存（含 xml/filename/platform/isReadOnly）。sessionStorage 在 Same Origin 的 reload/重建後仍保留，生命週期為單次 tab。

## 追記：examples dirty 狀態下「開新檔」流程中止修復（2026-09-06）

### 問題
Tauri 版實測：開啟 examples 下的 MCU xml → 修改成 dirty → 在 toolbar 按「開 PC 模式新檔」→ 出現存檔提醒按下「儲存」→ 跳出覆蓋 examples 警告按下「儲存」→ dirty 被清除，但編輯畫面停在原檔，沒有開出新檔。

### 根因（Technical Deep Dive）
`ui/src/bridge/tauri.js` 的 `case 'saveFile'/'saveFileAs'`（L188）在存檔路徑是內建範例目錄時，`save_file` 會拋出 `EXAMPLES_PATH` 錯誤，進入 catch 分支：

- 舊程式忽略 `_handleExamplesSaveDialog(xml)` 的回傳值，最後無條件 `return false`。
- 但 `_handleExamplesSaveDialog` 內部「覆蓋範例」成功時會 `dispatch saveCompleted`（→ `persistence.onSaveCompleted` → `setDirty(false)`，此為 dirty 被清除之來源）並回傳 `true`。
- 前端 `persistence.js _confirmSaveBeforeNew()`（L486）以 `saved !== false` 判斷存檔是否完成。因 `send('saveFile')` 回傳 false，此判斷結果亦為 false → 被視為「使用者取消」→ `startNewProjectFromHome()` 直接 early return，**開新檔流程被中止**。

→ 造成「存檔已成功（dirty 清除）但開新檔未發生」的矛盾行為。

### 修正
`case 'saveFile'/'saveFileAs'` 的 `EXAMPLES_PATH` 分支改為回傳 `_handleExamplesSaveDialog(xml)` 的真實結果（覆蓋成功 / 另存成功 → true；取消 → false），並於成功時補上 `_refreshAnchor()` 同步前端錨定。修正後 `_confirmSaveBeforeNew` 能正確判定「存檔已完成」，`startNewProjectFromHome` 得以繼續執行 `saveFileAs(newProject)` 開出目標平台新檔。

## 追記：「原專案已儲存」提示未等待確認就跳第五步（2026-09-06）

### 問題
實機發現：開新檔流程第四步「原始專案已儲存…」提示對話框跳出後，還沒按確定，第五步的「開新專案另存」對話框就馬上出現（Tauri）。

### 根因（Technical Deep Dive）
`ui/src/bridge/base.js` 的 `alert(message)` 呼叫 `this.send('alert', {message})` 但**沒有 return**。因此 `persistence.js startNewProjectFromHome` 的 `await window.CocoyaBridge.alert(msg)` 實際 await 到 `undefined` → 立即繼續 `send('saveFileAs', ...)` 跳第五步。

Tauri 端 `send('alert')` 內部是真正會阻塞的（`_handleNativeDialogs` → `await _showAlertDialog`，自訂 token 對話框，僅在 OK/Enter/Escape/背景點擊的 `settle()` 才 resolve），只是 `alert()` 沒把這個 promise 還回呼叫端。

### 修正
`base.js` 的 `alert()` 改為 `return this.send('alert', { message });`。修正後 Tauri `await bridge.alert(msg)` 會真正阻塞直到關閉提示。
- 安全面：不影響未 await 的既有呼叫（仍 fire-and-forget）；有 await 的呼叫原本就意圖等待，現才真正生效。其他 `await this.alert(...)` 呼叫點一併受惠。
- 限縮：VSIX `send()` 是 fire-and-forget（postMessage 無回傳值），`alert()` 回傳的是「postMessage 已送出」的 promise，無法等使用者關閉原生 information message；若 VSIX 也出現同類重疊，需改用前端自訂阻塞 modal（如 save-confirm 樣式）於 persistence.js 內直接呈現，不走 bridge。

## 追記：SAME_AS_CURRENT 提示後自動重試開新專案對話框（2026-09-06）

### 需求
「不能存到目前專案檔的位置」防呆提示出現後，希望自動再跳出「開新專案」另存對話框（第五步），讓使用者改選其他位置，而非就此中止。

### 修改
`ui/src/bridge/tauri.js` `case saveFile/saveFileAs` 原本以 `try/catch` 單次執行；改為 **防呆重試迴圈**（`MAX_SAME_AS_CURRENT_RETRY = 5`）：
- 成功 → `saveCompleted` + `_refreshAnchor` + return true。
- `SAME_AS_CURRENT` → alert 提示「不能存到目前專案檔的位置」後 `continue`，重新 `invoke('save_file')` 彈出另存對話框，讓使用者改選位置（這滿足「提示後自動再跳第五步」）。
- `EXAMPLES_PATH` → 既有 `_handleExamplesSaveDialog`，return done。
- `Canceled` / 其他錯誤 → return false。
- 連續 5 次均命中目前路徑 → alert「多次選到目前專案檔的位置，已中止操作。」+ return false（避免無限彈窗）。

安全性：後端 `save_file` 的 `SAME_AS_CURRENT` 只在 `save_as==true` 且『彈出對話框後』由使用者選到原路徑時才可能觸發；一般 `saveFile`（save_as=false）不彈對話框、不命中，不受影響。重試僅會重新彈出另存對話框，屬合理 UX。
