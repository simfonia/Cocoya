## 修復：reset firmware (燒錄系統) 失敗
錯誤 `invalid args 'serialPort' for command 'reset_firmware'` — Tauri / VSIX 皆無法燒錄 Maker Pi RP2040。

### 根因
提交 `3e56aa2` (2026-06-09, "支援 ESP32-S3 Sense") 為 Rust `reset_firmware` 新增必要參數 `serial_port: String` (mcu.rs:274)，但 `ui/src/bridge/tauri.js:330` 從未同步傳入 (該行自 `591c712d` 未改) → Tauri 回報缺少 `serialPort`。git blame 驗證。

### 修復
1. `ui/src/bridge/tauri.js:330`：加入 `serialPort: data.serialPort || ''` (Tauri 2.10.3 自動 camelCase→snake_case 對映；與 `pythonPath`→`python_path` 等慣例一致)。
2. `src-tauri/src/commands/mcu.rs`：`serial_port: String` → `Option<String>`；於 `is_serial` 分支以 `filter().ok_or_else()?()` 驗證非空 (UF2 模式不強迫填埠)。
3. `src/handlers/firmwareOps.ts`：移除未設值的 `srcPath`，改用 `flashSegments[0].path` (custom 與非 custom 均正確)。

### 技術深挖
- `is_serial = model.contains("CAMERA")||model.contains("FACTORY")||model=="custom"` (mcu.rs:299)。Maker Pi RP2040 非 serial → 走 UF2 磁碟複製分支；`serial_port` 僅 serial 分支檢核，故 `Option<String>` 對 UF2 無影響。
- Tauri invoke 命名慣例：JS camelCase / Rust snake_case 自動對映 (deploy_mcu `pythonPath`↔`python_path` 已驗證正常)。

### 驗證
- `node --check ui/src/bridge/tauri.js` → OK
- `cargo check` (src-tauri) → Finished，無錯誤 (5 警告皆既存)
- `npx tsc --noEmit -p tsconfig.json` → TSC_EXIT=0

### 下次啟動方向

## 修復二：Deep Repair (Clear MCU Files) — VSIX esptool 失敗
錯誤：`Failed to connect to Espressif device: Invalid head of packet (0x08)`

### 現象
- Tauri (正常)：`>>> [Deep Repair] Targeting port: COM6` -> `Interrupting...` -> `Deleting all files...` -> `[Done] Deep Repair successful` -> `Rebooting...`
- VSIX (失敗)：`esptool v5.3.0 ... erase-flash` -> `Invalid head of packet (0x08)`

### 根因
`src/handlers/firmwareOps.ts:184` `handleEraseFilesystem` 直接執行 `esptool erase-flash` (UART download-mode 擦除)，但 ESP32-S3 正執行 MicroPython，esptool 無法 sync。
- Tauri 走 `mcu.rs:221` -> `python -u deploy_mcu.py <port> --erase-filesystem` -> `deploy_mcu.py:erase_filesystem` (pyserial REPL `wipe()`)。
- VSIX 使用錯誤工具 (硬體擦除) vs Tauri (檔案清除)，功能不一致。

### 修復
`handleEraseFilesystem` 改為呼叫 `deploy_mcu.py --erase-filesystem`，mirror `handleSetupStableMode` 的 `extensionUri` 解析與 Rust mcu.rs:221-228 的 arg shape：
```
& "${ePython}" -u "${eScript}" "${ePort}" --erase-filesystem --lang "${eLang}" --tauri
```

### 驗證
- `tsc --noEmit -p tsconfig.json` -> TSC_EXIT=0

### 下次啟動方向
- 實機驗證 VSIX Deep Repair 印出 `[Deep Repair]...` 並清除檔案 (Tauri 既已驗證)。
- 審視 MSG_ERASE_START_REFLASH ("re-flash firmware") 文案對 filesystem wipe 而言誇張，建議校正語意。
