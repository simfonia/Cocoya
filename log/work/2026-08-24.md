## [已完成] Startup Home 除錯 — 開新專案流程雙平台修正

### 問題（使用者回報）
1. **VSIX**：首頁進入 PC 模式編輯後，按 toolbar「新增」選同樣 PC 模式 → 沒檢查 dirty，直接跳「另存新檔」對話框而不是開新檔
2. **Tauri**：整個開檔流程錯誤（先另存錨定 + 開新視窗）。正確語意應為：
   - 首頁 → 依選擇平台直接進入初始積木
   - 編輯畫面按 toolbar/新增 → 檢查 dirty → 依目前平台重建初始積木，不回首頁、不開新視窗、不跳另存

### 根因
- 上一輪 `startNewProjectFromHome()` 統一走 `_serializeAndSaveAs()` → `saveFileAs`（無 dirty 檢查、必跳另存對話框）
- Tauri 另掛 `_pendingNewWindowAfterSave` 旗標 → 存檔後 `create_window` 開新窗（流程全錯）
- VSIX 後端 `fileOps.handleNewFile` 本有完整「checkDirtyAndConfirm → 存回原檔 → postMessage resetWorkspace」，被前端繞過

### 修改內容
| 檔案 | 異動 |
|------|------|
| `ui/src/app/persistence.js` | 重寫 `startNewProjectFromHome()`：Tauri 走前端 `_confirmSaveBeforeNew()`（showSaveConfirm + saveFile 可判斷取消）；VSIX 送 `newFile` 給後端做 dirty 檢查。跨平台先 `setPlatformUI`。移除 `_serializeAndSaveAs()`；新增 `_getCurrentXmlWithPlatform()` / `_confirmSaveBeforeNew()`；`onSaveCompleted()` 移除 `_pendingNewWindowAfterSave` 區塊；`resetWorkspace()` 結尾改 `hideStartupHome()`（不再回首頁） |
| `ui/src/ui/base.js` | toolbar 新增選單 `handleOption` 移除 `_pendingNewWindowAfterSave` 旗標設定；註解更新 |

### 技術深挖 (Technical Deep Dive)
- **VSIX bridge.send() 無回傳值**（vsix.js L54-61 postMessage fire-and-forget），前端無法得知存檔對話框是否被取消 → VSIX 的 dirty 檢查必須留在後端（handleNewFile 確認後才送 resetWorkspace），不可在前端 await 判斷
- **Tauri bridge.send() 有回傳值**（tauri.js saveFile case return true/false）→ 前端 `_confirmSaveBeforeNew` 可靠判斷「取消存檔即中止開新」
- **未錨定編輯合法化**：新語意下從首頁進入編輯區不立即錨定；第一次明確存檔才確立專案根（VSIX performSave 無 currentFilePath → 存檔對話框；Tauri save_file path_to_save None → fallback 對話框，兩端皆已內建此 fallback）
- **resetWorkspace 移除 showStartupHomeIfNeeded()**：否則 VSIX handleNewFile → resetWorkspace 又會跳回首頁，違反「開新不回首頁」

## [已完成] 開新專案「先確認、後破壞」：取消另存不再留下未錨定未命名

### 問題（使用者回報）
1. 編輯中按新增（非 dirty / 跨平台）：**對話框跳出前**就 `resetWorkspace()` → 原檔顯示被清成未命名；按取消後停在未錨定狀態回不去
2. 首頁選平台：跨平台時 `resetWorkspace()` 內 `hideStartupHome()` 讓首頁在對話框前消失（「有時」= 僅跨平台選擇觸發），露出底下未命名專案；取消後無法回首頁

### 根因（同類 bug）
不可逆的狀態破壞（清工作區、清檔名、隱藏首頁）發生在「另存對話框結果確認之前」。全面稽核：Tauri `_confirmSaveBeforeOpen`（開啟/範例）與 closeEditor 流程安全；開新流程雙平台皆有此問題。

### 修正：「先確認、後破壞」原則
| 檔案 | 異動 |
|------|------|
| `ui/src/app/persistence.js` | ① `startNewProjectFromHome()` 雙平台統一：dirty 檢查 → 記錄 `_pendingNewProjectPlatform` → `_serializeAndSaveAs('newProject', targetPlatform)`（XML 直接標目標平台），**對話框前完全不動 UI/工作區/首頁**。② `onSaveCompleted(filename, tag)` 收到 `tag='newProject'` 才套用：跨平台 `setPlatformUI` + 新增 `_applyInitialBlocks()`（清工作區+建初始積木，但**不清檔名、不碰首頁邏輯**）。③ 移除重複的舊版 helper |
| `ui/src/app/controller.js` | `saveCompleted` handler 傳遞 `m.tag` |
| `ui/src/bridge/tauri.js` | `saveFileAs` 成功後 dispatch `saveCompleted` 帶上 `data.tag` |
| `src/handlers/fileOps.ts` | `handleSaveFileAs` 的 `saveCompleted` postMessage 帶上 `message.tag` |

### 技術深挖 (Technical Deep Dive)
- **tag 回傳鏈的必要性**：VSIX bridge.send() 是 fire-and-forget，前端無法得知另存是否被取消；若只靠前端旗標，取消後殘留旗標會在下一次普通存檔時誤觸重建積木（資料丟失風險）。改由後端在 saveCompleted 回呼帶回 `tag='newProject'`，只有「開新專案的另存成功」才會套用初始積木 —— 取消 = 完全無副作用
- **`_applyInitialBlocks()` vs `resetWorkspace()`**：後者會 `updateFileStatus('')` 清檔名並觸發回首頁邏輯，不適合錨定成功後的場景
- **磁碟暫態**：另存當下寫入的是「目前工作區內容 + 目標 platform 屬性」（跨平台時積木為舊平台），存檔成功後記憶體立即重建為新平台初始積木；下次 autoBackup/存檔即寫入正確內容，屬可接受的短暫不一致

### 驗證
- [x] node --check（persistence/controller/tauri）、tsc --noEmit EXIT=0、ui build 成功
- [ ] 實機：(a) 首頁選平台→取消另存 → 首頁仍在、無未命名殘留 (b) 編輯中跨平台新增→取消 → 原檔完整保留 (c) 成功路徑 → 另存後自動重建目標平台初始積木、檔名正確

## [已完成] 追加：另存新專案寫入「目標平台乾淨初始 XML」，消除磁碟暫態

### 問題（使用者回報）
開啟 PC 專案 A.xml（未 dirty）→ 新增 MCU 專案存為 B.xml → 未編輯再開啟 B.xml → **內容是 A 的積木但平台顯示 MCU**。

### 根因
上一輪「先確認、後破壞」設計中，另存當下寫入的是「目前工作區序列化 + 目標 platform 屬性」（即 A 的內容被標成 MCU 存進 B.xml），記憶體的初始積木重建只發生在前端；重開檔讀到的就是磁碟上的暫態內容。

### 修正
- `persistence.js` 移除 `_serializeAndSaveAs()`，新增 `_getInitialProjectXml(platform)` 靜態模板：
  - PC：`py_definition_zone` + `py_main`
  - MicroPython：`py_definition_zone` + `mcu_main(DO) > py_loop_while(CONDITION) > py_logic_boolean(True)`（欄位/輸入名稱與 lifecycle.js `createDefaultBlocks` 完全對應）
- 另存 B.xml 時直接寫入乾淨初始專案，**絕不帶入原專案內容**；`_getCurrentXmlWithPlatform()` 保留僅供 dirty 存回原檔使用

### 技術深挖 (Technical Deep Dive)
- `createDefaultBlocks()` 綁定實際畫布（initSvg/render/toolbox offset）無法離屏產生 XML，故改用靜態模板；模板需與 createDefaultBlocks 同步維護（若未來改變初始積木組成需兩處同改）
