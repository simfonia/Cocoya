## 技術深挖 (Technical Deep Dive)

### 1. Web 模擬終端機與 Python `input()` 的雙向通訊架構 (方案 A)

Cocoya 的底部終端機原先為單向輸出模擬（stdout/stderr $\to$ Tauri 事件 $\to$ `appendTerminal`）。
當執行到含有 `input()` 的 Python 程式碼時，子進程因 stdin 無對應輸入端而會阻塞或丟出 `EOFError`。

本次採用方案 A（管道雙向注入）：
1. **後端管道接管 (`src-tauri/src/commands/python.rs`)**：
   - 子進程配置加入 `.stdin(Stdio::piped())`。
   - `child.stdin.take()` 取出 `ChildStdin`，建立 `mpsc::channel::<String>()`。
   - 由背景執行緒持有 `ChildStdin` 與 receiver，收到字串後自動補上 `\n` 並立即 `flush()`。
   - 將 sender 保存於 `AppState.python_stdin_senders`（以 window label 索引）。
   - 新增 `send_stdin(window, state, text)` 指令，透過 sender 安全寫入。
   - 在 `stop_python` 與 `CloseRequested` 時主動 `remove` sender，Sender drop 觸發 channel 關閉與 stdin pipe 關閉，確保進程樹順利釋放。
2. **前端輸入列與回顯 (`ui/src/ui/terminal.js`, `style.css`)**：
   - 在 `#terminalTextPane` 底部加入 `#terminalStdinRow`（含 prompt 符號 `>`、文字輸入框與 Enter 送出按鈕）。
   - 使用者按 Enter 或點擊送出按鈕時，將文字以 `term-info` 樣式注入終端機畫面（模擬真實終端機的使用者輸入回顯），並透過 `bridge.send('stdinSend', { text })` 傳遞給後端。
   - 程式執行完畢或點擊停止時，自動隱藏輸入列並清空暫存輸入。

### 2. 提示文字阻塞根因分析與非行阻塞即時串流 (Chunk Streaming)

#### 問題現象
執行 `input("hello: ")` 時，`hello: ` 完全沒有印在終端機上，只有在點擊「停止」或「再次執行」中斷前次程式時，`hello: ` 才會突然出現。

#### 根本原因
- Python 的 `input("hello: ")` 輸出的提示文字**結尾不包含換行符 `\n`**。
- `src-tauri/src/commands/python.rs` 原先讀取 stdout/stderr 的迴圈寫法為：
  ```rust
  let mut reader = BufReader::new(stdout);
  match reader.read_until(b'\n', &mut buffer) { ... }
  ```
- `read_until(b'\n')` 必須遇到 `0x0A` (`\n`) 才會回傳；若未遇到 `\n`，執行緒將卡死在系統呼叫中等待，直到子進程結束關閉 pipe（EOF），`read_until` 才會釋出剩餘 byte。

#### 解決方案
重構為類似 `stream.rs` 的非行阻塞即時讀取：
```rust
let mut reader = stdout;
let mut buf = [0u8; 1024];
let mut pending = Vec::new();
loop {
    match reader.read(&mut buf) {
        Ok(0) => break, // EOF
        Ok(n) => {
            pending.extend_from_slice(&buf[..n]);
            let tail_len = crate::commands::mcu::stream::utf8_incomplete_tail_len(&pending);
            let ready_len = pending.len() - tail_len;
            if ready_len > 0 {
                let ready_bytes: Vec<u8> = pending.drain(..ready_len).collect();
                let raw = String::from_utf8_lossy(&ready_bytes);
                let cleaned = strip_ansi_codes(&raw);
                let _ = window_clone.emit_to(&run_stdout_label, "python-log", cleaned);
            }
        }
        Err(_) => break,
    }
}
```
配合 `utf8_incomplete_tail_len`，兼顧了「只要有字元即時輸出（即刻顯示提示字元）」與「多位元組中文字元跨緩衝區不碎裂亂碼」的特性。
