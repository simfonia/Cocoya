# 工作日誌 2026-10-13

## #task[cocoya DM 分類統計] 頂部常駐統計列＋分類篩選

使用者需求：DM P2/P3 的統計數據（分類及總數）顯示在視窗最上方。兩個缺點：
1. 只有總數、沒有分各分類統計數
2. P2 統計數據在中欄上方，但縮圖在右欄下方；管理或刪除縮圖時要捲下畫面，此時看不到數據

**選案**：使用者選 **A**（中欄保留完整統計表格，頂部只放精簡列）＋ 加 chips 篩選縮圖；
其餘兩項（類別不平衡警示、匯出前低樣本提示）列 backlog。

### 根因（缺點 2）
統計原本只渲染在中欄 `#view-label-stats`，而該節點位於
`.dataset-manager-body`（`overflow:auto` 的捲動容器）之內 → 縮圖牆一多就要捲動才看得到。
「把中欄統計做成 sticky」是錯的方向：P2 的 body 是 grid、P3 是 flex column，
兩者的高度鏈都不能可靠解析（本專案 2026-08-07 已因 grid 子項 `height:100%` 無法解析
吃過縮圖捲動失效的虧）。

### 定案
把統計列放到 `.dataset-manager-body` **之外**，成為 `.dataset-manager-dialog`
（`flex-direction:column`）的直接子項 → 本列自然常駐、不隨縮圖牆捲動，
且**不需要 `position:sticky`**，完全不碰高度鏈。

### 技術深挖 (Technical Deep Dive)

#### 1. 「容器在捲動容器之外」才是真不變式，不是「有這個 id」
掃字串 `id="dataset-global-stats"` 存在與否，**無法區分**「放在 body 外（正確）」
與「放在 body 內（就是 bug 本身）」這兩種寫法。故守門斷言**索引順序**：
`html.indexOf('id="dataset-global-stats"') < html.indexOf('class="dataset-manager-body"')`。
並附變異自檢：把統計列區塊搬進 body 內，自檢必須確認變異真的生效。

#### 2. 統計更新必須寫在早退分支「之前」——順序是契約
`renderStatsPanels()` 的第一個分支是 `if (viewStats) { ...; return; }`。
**P3 標註模式時 `#view-label-stats` 的 DOM 仍然存在**（只是父面板 `display:none`），
所以該分支照樣命中並 return。若把 `renderGlobalStatsBar()` 寫在這個 return 之後，
P3 就永遠不會更新頂部列——而且沒有任何行為測試會紅（因為 P3 走的是另一條 UI 路徑）。
故以兩條掃描型守門釘死「函式本體含 renderGlobalStatsBar」＋「其位置早於
`getElementById('view-label-stats')`」，並做**真實變異測試**：
實際刪掉 `renderGlobalStatsBar();` 那一行 → 2 條守門正確報紅（17 pass / 2 fail），再還原。

#### 3. 篩選的索引映射：錯位就會刪錯圖
篩選後 grid 顯示的是 `state.images` 的子集，其序號與 `state.images` 不同。
若沿用舊寫法 `onDeleteImage: (idx) => handleDeleteImage(idx)`，`idx` 是**篩選後的位置**，
會刪到別張圖——且刪的是磁碟檔案，屬不可逆損害。
故抽出 `renderImageGridFiltered()`，由 `statsFilteredEntries()` 回傳
`{ img, index }`（index 恆為 `state.images` 內的原始索引），4 處原本直接呼叫
`renderImageGrid(..., state.images, ...)` 的列表模式呼叫點全數改走它。

#### 4. 為何只有分類型別可篩選（兩個獨立的理由）
- **語意**：偵測/循跡的 `label_counts` 是「框數/線段數」，不是每張圖的類別，
  用同一組 chips 去篩選影像是錯的。
- **可行性**：P3 時 `#dataset-image-preview` 已被 annotation 3 欄 layout 取代而不存在，
  點了只改狀態、畫面零反應 → 違反「看起來能點就必須真的有意義」。
故 `isStatsFilterable()` = `isClassificationType() && !annotationMode.isActive`。
（第二條是施工中實讀碼發現的真實不一致，非一開始就想到。）

#### 5. 「看起來能點」的呈現判據：button vs span
`renderGlobalStats` 僅在 `filterable && typeof onChipClick === 'function'` **兩者皆成立**
時才渲染 `<button>`；否則渲染 `<span>`。避免不可篩選的類型（偵測/循跡/表格）
出現「有按鈕外觀卻沒反應」的誤導。兩條測試分別守住「缺 filterable」與「缺回呼」。

#### 6. 計數單位不得兩處分歧
頂部列的單位（框數/線段/樣本數）與中欄表格表頭**必須一致**。兩處都走同一組
`typePolicy` 判定（`needsUnclassifiedCheck` / `line_following`），並在測試中以
**同一張真值表**對帳兩者。這條特別重要：2026-10-01 曾有人把三分支改寫成
`isClassificationType(t) ? SAMPLE : (line ? LINE : BOX)`，看似等價，
實際上讓 `table`／`feature` 顯示「標註框數」——新增第二處顯示時極易重犯。

#### 7. 篩選狀態的失效時機（4 個，漏一個就會出現「點了沒反應」或「圖不見了」）
1. 篩選目標被刪除/改名 → `renderStatsPanels` 用 `hasOwnProperty(label_counts)` 偵測並解除。
2. 拍到「非目前篩選分類」的圖 → 必須解除，否則新圖不在結果內，使用者會以為沒拍進去。
3. 新會話（`enterWorkspace`）與清除資料 → 不繼承上一次的篩選。
4. 篩選後零結果 → 顯示 `STATS_FILTER_EMPTY`，**不可回退成「尚無影像資料」**
   （那會讓人以為整批圖全掉了）。

#### 8. P1 入口頁的隱藏陷阱
`showEntryPhase()` 原本只隱藏 `.dataset-manager-body`。統計列在 body **之外**，
不會被連帶隱藏 → P1 會出現一條空統計列。已補顯式 `display:none`，
`enterWorkspace()` 相對回復。

#### 9. 測試替身必須反映真實介面契約
第一版 `renderGlobalStats` 測試的假容器只有 `{ innerHTML: '' }`，
在 `filterable` 路徑立刻 `TypeError: container.querySelectorAll is not a function`。
這正是「替身缺方法＝沒測到綁定那一段」：若不修替身而改成不測 filterable，
就會漏掉 click 綁定整段。已改為 `makeStatsContainer()`（攔截 innerHTML setter、
依 `data-label` 重建假 chip 節點），並新增一條**真的觸發 onclick** 的行為測試，
斷言 `['paper', 'rock', null]`——其中「全部」必須回 `null` 而非空字串
（空字串會變成一個永不成立的篩選條件）。

#### 10. CRLF 讓 `'\n}\n'` 函式邊界失效
第一版守門用 `src.indexOf('\n}\n', start)` 截函式本體。本專案全檔 CRLF，
該字串永遠匹配不到 → indexOf 回 `-1` → `slice(start, -1)` 產生負長度例外
（實測 `length ('-58830') must be a non-negative value`）。
此失敗**表現為 assertion 錯誤**，極易誤判成「守門邏輯寫錯」。
已改用行首 `}` 的正規邊界 `/^function renderStatsPanels\(\)[\s\S]*?\n\}/m`，
並在註解記下原因（與 AGENTS.md 行尾三層防護同一類坑）。

### 1. P3 標註頁上方出現 `title="十字尺規顏色">尺規`（HTML 語法錯誤）
**根因**：`ui/annotation.js` 的 `<label class="dataset-annotation-crosshair-picker" id="...">`

當成節點內容輸出 → 工具列上方多出一行詭異可見文字。

**守門**：新增掃描型紅線「HTML 註解不得夾在標籤屬性列之間」＋變異自檢

### 實作落差（我上一輪做錯的地方）

**blob 所有權陷阱（已查證，兩種來源不可混為一談）**：
| 來源 | 型態 | 處理 |
|---|---|---|
| live 拍照 `ui_layout.js` `URL.createObjectURL(blob)` | `blob:` | 前端持有 → **必須 revoke** |
| 匯入資料夾 VSIX `asWebviewUri`／Tauri `convertFileSrc` | 平台檔案 URI | 不是我們建的 → **不可動** |

### 6. P3 按「第二個分類 chip」後綠色焦點框消失（篩全部或第一分類卻正常）
**根因（巧合式正確，不是隨機 bug）**：P3 縮圖列改渲染 `statsFilteredEntries()`（`state.images` 的子集）後，
DOM 序號與 `annotationMode.currentIndex`（**絕對索引**）脫勾。原先寫法是
`item.classList.toggle('current', idx === state.annotationMode.currentIndex)`——
只有在「篩選結果恰好從第 0 張開始、且當前圖在子集中的位置等於其絕對索引」時才會命中。
「全部」與「第一個分類」正是這兩種巧合情況，故表現為「某些 chip 正常、某些失效」。

**修正**（`ui_layout.js`）：
- 新增 `statsVisiblePositionOf(absIndex)` → 回傳該圖在**篩選後陣列**中的位置（找不到 -1）。
- `updateThumbnailHighlight()` 改為先算 `pos = statsVisiblePositionOf(currentIndex)`，再以 `idx === pos` 比對。
- 勾號（已標註 ✓）原本讀 `state.images[idx]` —— 篩選後同樣錯位，改讀 `entries[idx].img`。
- `currentItem` 同步改用 `items[pos]`。

**為何是掃描型守門而非行為測試**：此函式是 `ui_layout.js` 的模組內部函式（非 export），
既有「手動改狀態再自己呼叫 render()」式的行為測試在 mutation 下仍會全綠（本專案已記載的假安全感模式）。
故新增 2 條掃描原始碼的契約測試，且斷言**負向條件**（不得出現 `idx === state.annotationMode.currentIndex`）。

### 7. 分類篩選下 ↑/↓ 鍵仍會跳到篩選外的照片
**根因**：兩個 controller 的 keydown 直接呼叫 `navigateToImage(currentIndex ± 1)`，

  邊界直接 `return`（**不做循環**）；當前圖不在篩選內時（剛切 chip）從頭/尾起算，不整個失效。

  「currentIndex=1 按 ↑ → nav 0」會變成在驗證替身自己。
