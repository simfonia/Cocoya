### [實作成果]

積木樣貌：`計算點 [A]、[B]、[C] 之夾角 類型 [▼]` → 傳回數值。

生成 Python (以 `interior` 為例)：
```python
import math
def cocoya_calc_angle_3pts(a, b, c, mode='interior'):
    # a, b, c: (x, y) coordinate tuples; vertex is the middle point b
    # signed>0 means CCW rotation from ray BA (toward a) to ray BC (toward c)
    if not a or not b or not c: return 0
    v1x, v1y = a[0]-b[0], a[1]-b[1]
    v2x, v2y = c[0]-b[0], c[1]-b[1]
    dot = v1x*v2x + v1y*v2y
    cross = v1x*v2y - v1y*v2x
    signed = math.degrees(math.atan2(cross, dot))
    if mode == 'signed': return signed
    interior = abs(signed)
    return (360 - interior) if mode == 'exterior' else interior

angle = cocoya_calc_angle_3pts((110, 220), (320, 240), (530, 260), 'interior')
```

## 技術深挖 (Technical Deep Dive)

### 為何選用 `field_dropdown` 而非 `field_checkbox`
勾選框語意不明（「未勾 = 內角？」）；且「外角」在三角形 (180°−內角) 與自由旋轉關節 (360°−內角) 定義不同，容易混淆。
改用下拉 (mcu_car / ai_inference 既用 pattern)：三種模式明確互斥、預設 `interior`，並額增 **有符號角** 供手勢方向判斷。

### 方向約定推導
`atan2(cross(BA, BC), dot(BA, BC))`。驗證 (數學座標 y 向上)：
- `A=(1,0) B=(0,0) C=(0,1)`：BA 指向右、BC 指向上，右→上為逆時針 ⇒ `signed = +90°` ✓
- `A=(0,1) B=(0,0) C=(1,0)`：BA 指向上、BC 指向右，上→右為順時針 ⇒ `signed = −90°` ✓
⇒ **正值 = A→C 逆時針** 確認。

⚠️ OpenCV 像素座標 y 軸向下，故圖形上顯示的旋轉方向與數學座標相反，但 **數值規則不變**：正值始終 = 由 A 射線逆時針到 C 射線。

### 函數鍵衝突防護
`detect_punch` 使用 `cocoya_get_angle` (作用對象為 `.x/.y` 的 Landmark 物件；鍵 `func_calc_angle`)。
新積木採 **Tuple (x,y)** 輸入，函數改名 `cocoya_calc_angle_3pts`，鍵獨占 `func_calc_angle_3pts` → 兩者並存；
`import_math` 鍵共用 (idempotent)。
