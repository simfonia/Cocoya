### 技術深挖 (Technical Deep Dive)

#### 1. Blockly 12.3.1 的 toolbox 分類文字是 DOM，不是 SVG
- 分類列 class chain：`.blocklyToolboxDiv` 底下 `.blocklyToolboxCategoryContainer` 內含 `.blocklyToolboxCategory`（列）與 `.blocklyToolboxCategoryLabel`（文字）。
- Blockly 執行期以 `register` 注入 CSS：`.blocklyToolboxCategoryLabel { font: 16px sans-serif; }`、`.blocklyToolboxCategory { height: 22px; line-height: 22px; }`。
- **關鍵**：只放大 font-size 會被固定 22px 列高裁切 → 必須 label 與列高**同源同步縮放**，才能維持垂直置中且不破版。
- 覆蓋手法：提高特異度 `.blocklyToolboxDiv .blocklyToolboxCategoryLabel`（0,2,0 勝 0,1,0），**不依賴載入順序**（Blockly 是 runtime 注入，順序不可控）。
- 因 Blockly 於載入時量測 toolbox 寬度決定 flyout 位置，調值需**重新載入**才完全正確（本輪設計即為「改檔 + reload」）。

#### 2. DM 不動 43 處 calc：用「變數重綁定」做模式映射
- 昨日已把 DM 43 處字級寫成 `calc(Npx * var(--dsm-font-scale))`。今日**不改這 43 處**，改為在 overlay 依模式重新綁定上游：
  - `.dataset-manager-overlay` → `--fs-p2`（P2 基準）
  - `.dataset-manager-overlay.dataset-entry-phase` → `--fs-p1`
  - `.dataset-manager-overlay.dataset-annotation-fullscreen` → `--fs-p3`
- 自訂屬性隨 DOM 樹繼承，故 modal 內所有子樹自動換算；模式切換即換上游，元件 CSS 零改動。
- **為何不用 `:has()` 判斷 P1**：`#dataset-entry-view` 首次開啟後就常駐 DOM（只是 `display:none`），`:has(#dataset-entry-view)` 在 P2 也會命中。改用**顯式 phase class**（`showEntryPhase` 加、`enterWorkspace` 移），語意明確且連 header 一起跟 P1 變數。
- 行內樣式（JS template）處以 `var(--dsm-font-scale, 1)` 帶 fallback，避免在 overlay 外被注入時 calc 失效導致字級整個掉回繼承值。

## [追加] 實機回饋：E 設定下拉（含韌體子選單）文字放大後換行難看

### 現象（使用者回饋）
- `--fs-e: 1.5` 後，toolbar 最右「設定」下拉的文字被擠成兩行；展開後的「韌體設定」子選單同樣。
- H 回報 OK（`--fs-h: 1.2`）。

### 根因（純 CSS 佈局，非字級設定錯）
- `.dropdown-content` 與 `.dropdown-submenu .submenu-content` 都是 `position: absolute` 且**只給 `min-width`（160px / 220px）**。
- 絕對定位且未指定 width 時走 **shrink-to-fit**：`available = 定位父層寬度`，而父層 `.toolbar-dropdown` 只是 **32px 寬的圖示**→ 收縮到 min-width 後**文字只能在框內換行**。
- 換言之：字級放大會讓文字變寬，但**框寬被 min-width 釘死**，所以「看起來像字級壞了」，其實是**容器寬度沒跟著字級長**。

### 修正（`ui/src/style.css`，三處）
| 選擇器 | 新增 |
|---|---|
| `.dropdown-content` | `width: max-content;` + `max-width: calc(100vw - 24px);` |
| `.dropdown-submenu .submenu-content` | `width: max-content;` + `max-width: calc(100vw - 24px);` |
| `.dropdown-item` | `white-space: nowrap;` |

- `width: max-content`＝**框寬隨內容（含字級）成長**；`max-width: 100vw-24px`＝極長文案時的換行護欄（避免溢出視窗）。
- 設定選單仍是 `right: 0` 向左展開、子選單 `right: 100%` → 變寬時自然往左長，不影響既有版面。
- 附帶修好同類問題：`#ai-dropdown .ai-dropdown-content`（同用 `.dropdown-content`）。

### 驗證
- `npx vite build` PASS；產物 CSS 實測：`.dropdown-content{...min-width:160px;width:max-content;max-width:calc(100vw - 24px)...}`、`.dropdown-submenu .submenu-content{...width:max-content...}`、`.dropdown-item` 具 `white-space:nowrap`；`--fs-e:1.5` / `--fs-h:1.2` 已入 bundle。

### 行為準則更新（重要）
> 字級放大後若「文字換行／被裁切」，**第一優先檢查該文字所在容器的寬高是否為固定值**（`min-width`/`width`/`height`/`line-height`）。正解是讓容器跟著字級成長（`max-content`／同一支 `--fs-x` 的 calc），**不是把字級調回去**。## [P2 UI 版面優化] live 標籤管理收斂＋啟動預覽獨立行（2026-09-16）
