### 案 1：模板同步 WinError 123
- **症狀**：`[Remote] 模板同步` 時 `[WinError 123] ... '\\?\C:\...\train_templates\classifier/classifier_train.py'`
- **根因**：Rust `BaseDirectory::Resource` 的 `resolve()` 回傳 canonicalized 路徑（`\\?\` 前綴）→ sidecar `__file__` 帶前綴 → `local_templates_root` 繼承；`\\?\` 模式下 Windows 不正規化分隔符，而 `rel` 為 `/` 分隔，`os.path.join` 組出混合斜線路徑 → `zf.write` 炸。
- **為何資料集同步（403 檔）沒炸**：資料集根目錄來自前端，無 `\\?\` 前綴。
- **修正**（`resources/dataset_manager/dataset_sidecar.py`）：
  - `local_templates_root` 剝掉 `\\?\` 前綴（line ~481）
  - 兩處 zip 打包（line 446 資料集、line 522 模板）`rel.replace("/", os.sep)` 防禦
- **教訓**：`\\?\` 長路徑模式不做分隔符正規化，路徑組裝必須全用 `os.sep`。

### 案 2：選「無」卻下載殘留 keras
- **根因**：下載對遠端 output 目錄照單全收；目錄共用且不清空，前次/殘留 `gesture_model.keras` 被誤下載。
- **修正**（三層）：
  1. 訓練前 `rm -rf <remote_output_dir> && mkdir -p`（清空，根治）
  2. 下載白名單：只抓 `project_name` 前綴 + `labels.txt`；`model_output=none` 跳過 `.keras`
  3. `model_output=none` 時本地 `_pick` 不掃 keras（本地殘留不會被誤報 `kerasPath`；本地不刪檔，保留歷史產物）

### 案 3：本地 TFLite 轉換卡住無輸出
- **診斷歷程**：
  - PYTHONUNBUFFERED → 無效（連 pid 後一行都沒有）
  - 獨立重現同 Popen 呼叫：6 秒全流程完成 → 腳本/呼叫方式無問題
  - 進程內執行（importlib + redirect_stdout Tee）：卡在 `import tensorflow` → 工作執行緒 + Windows DLL loader lock 死結
  - 使用者回報 `本機 python` = 本地訓練成功轉換的同一個 WPy python → python/TF 無辜，卡的是 sidecar→Tauri 承載環境
- **根因**：sidecar 承載自 Tauri 的環境雜訊變數讓子進程 TF import 卡死（進程內則因 loader lock 於非主執行緒卡死）。
- **最終修正**：子進程 + **環境白名單**（只繼承 SystemRoot/TEMP/PATH/USERPROFILE 等必要系統變數）+ `stdin=DEVNULL` + `CREATE_NO_WINDOW` + `PYTHONUNBUFFERED=1` + 60 秒 watchdog（無輸出自動傾印 sidecar 環境至 `%TEMP%\cocoya_sidecar_env_dump.txt`）。
- **附帶修正**（`_local_convert_tflite.py`）：`convert_tflite()` 新增 `need_rep` 參數——只有 int8 量化需要 representative dataset；純 f32 完全跳過樣本掃描（此前 f32 也白掃 400 張圖）。
- **實測**：int8+f32 成功產出 `classifier_dataset.tflite`（2820 KB, UINT8）+ `classifier_dataset_f32.tflite`（9331 KB）；量化比 30% 正常。
