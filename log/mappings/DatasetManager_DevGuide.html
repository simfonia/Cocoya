Dataset Manager 開發手冊 (Dev Guide)

建立：2026-09-01（Stage 6 切片 2，對應重構計畫「文件責任矩陣」）。責任：開發 SOP——新增資料集類型、i18n key、theme token、adapter 與測試流程。契約細節見 backend_api_manifest.md、公開 API 見 DatasetManager.html、雙平台 parity 見 DatasetManagerParityMatrix.md。

1. 新增資料集類型 (project type) SOP

  1. spec.js：擴充 projectType 清單與 validate() 分支（回傳 { ok, errors, warnings } 結構化結果，禁止回傳文案）。
  2. ui/modal.js 的 projectTypes 選單常數（經 buildModalTemplate 注入）。
  3. ui_layout.js 縮圖點擊分流（state.annotationMode.mode）與匯出前未標註/未分類檢查（application/exportUseCases.js）。
  4. 訓練模板（resources/dataset_manager/train_templates/）與 sidecar 支援；訓練集切分必須分層抽樣（AGENTS.md 鐵律）。
  5. i18n：VALIDATE_* 文案 zh-hant/en 同步補 key。

2. i18n key SOP

  • 文案鍵一律 DSM_*，呼叫 t('KEY', fallback, ...args)（i18n.js 會自動加前綴；嚴禁寫 t('DSM_X') 造成雙重前綴）。
  • 新增 key 必須同時補 i18n/zh-hant.js 與 en.js，跑 node temp_scripts/i18n_parity_scan.cjs 驗證兩語系集合一致。
  • 佔位符 %1 %2 由 t() 全域 replace。
  • 刪 key 前須以 parity scan + Select-String 確認無使用處；刻意保留須在呼叫端留註解（例：CLOSE_UNSAVED_CONFIRM）。

3. 主題 token SOP

  • 顏色一律用 --dsm-* token（定義於 dataset_manager.css 的 :root，不得掛 dialog——theme_manager cssVars 掛 body 層級）。
  • 新 token 須同步三件事：CSS :root 預設值、body.vscode-dark/high-contrast 覆寫、三主題 theme_manager/themes/cocoya_{light,dark,candy}.js 的 cssVars（theme_manager 不清舊 cssVars，light 也要定義以免殘留）。
  • 深色值目前雙來源（vscode-dark 覆寫 vs cocoya_dark cssVars）為已知債，見 todo。

4. Bridge adapter / 測試 SOP

  • 通訊只寫在 io/bridge.js：新增 command 走 datasetBridge.request({ command, payload, resultCommand, timeoutMs })；事件訂閱走 subscribe/unsubscribe + dispose。
  • 後端回傳鍵名 serde camelCase（例：isAnchored、projectRoot）；新增 Rust → JS 型別須實機驗證欄位名。
  • 錯誤碼契約：PROGRESS_NOT_FOUND、PROJECT_NAME_INVALID、IO_ERROR（save 另有 CODE: message 前綴）。
  • 測試：Node 測試放 *.test.mjs（node --test，不打包）；每層檔案位置見 FILE_STRUCTURE.md。
