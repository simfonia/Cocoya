3. 封包欄位偏移（解析契約，測試已鎖）

V2 RETURN_BLOCK(0x1C) data：0=ID(1) 1=level(1) 2=xCenter(2) 4=yCenter(2) 6=width(2) 8=height(2)
                            10=nameLen(1) 11=name(n) 11+n=contentLen(1) ...
V2 RETURN_ARROW(0x1D) data：0=ID(1) 1=level(1) 2=xTarget(2) 4=yTarget(2) 6=angle(2, 帶號 -90~90) 8=length(2)
                          （官方 Result.cpp 的 union 佈局 first/second/third/fourth = offset 2/4/6/8；
                            協定文件表格「length offset 7」為筆誤）
V2 RETURN_ARGS(0x1A)  data：0=totalIntArgs(1) 1=retValue(1) 2=arg0_int(2) ...
V1 RETURN_INFO(0x29)  data：5×int16
V1 RETURN_BLOCK(0x2A) data：0=x(2) 2=y(2) 4=width(2) 6=height(2) 8=ID(2)
V1 RETURN_ARROW(0x2B) data：0=xOrigin(2) 2=yOrigin(2) 4=xTarget(2) 6=yTarget(2) 8=ID(2)
                      （V1 無原生 angle/length → Cocoya 以起點→終點換算，語意對齊 V2）
官方範例幀（HUSKYLENS Protocol.md，可直接當測試向量）：
  55 AA 11 0A 2A 2C 01 C8 00 0A 00 14 00 01 00 58  → x=300 y=200 w=10 h=20 ID=1
注意：count() / get_id_at() 以 sorted(blocks.keys()) 為序，代表「本次請求命中的 ID 集合」，非硬體回報順序。

3b. 循線向量的起點語意（兩代不同，影響循跡寫法）

V1V2
起點在線上（線的近端點，座標系 320x240）固定為畫面下緣中點 (320, 480)（座標系 640x480）
向量語意線的局部方向（貼線）瞄準方位（pure pursuit；官方文件明載「Level 1 向量起點為畫面下緣中點、垂直線為 0°、順時針為正；Level 2 向量起點為 Level 1 終點，以便做多級向量相加」）
角度可用性協定無此欄 → Cocoya 以 atan2(dx, dy) 換算原生 int16 欄位
急彎行為方向＝線當下方向，較貼線瞄準遠端點 → 彎道會切內側（pure pursuit 固有）；縮短 lookahead（length 小）、混用橫向偏移 (xTarget-320)、用 Level 2 預判曲率可改善
待實機確認：V2 的 level 欄（offset 1）標示向量層級；官方 Python 範例以「有序清單 + level 判斷」取用（getCurrentBranch/getBranch），代表同一演算法可能回傳多筆 ARROW。 本模組目前以 arrows[ID] 字典儲存（同 ID 後者覆蓋），已保留 level 欄備用；Level 2 的 ID 對應關係與是否需改為清單結構，待實機驗證後決定（見 backlog）。

3c. 實務：V2 固定起點下如何「保持在線中位」（三解法）

V2 的 angle 同時混合了「橫向偏移」與「航向」，因此單用角度＝瞄準遠端點（pure pursuit），急彎會切內側。三種做法：

解法做法評語
B（最接近 V1 手感）用兩級向量還原兩點：near=(L1.xTarget, L1.yTarget)、far=(L2.xTarget, L2.yTarget) → e = near.x − 320（P）、slope = (far.x−near.x)/max(far.y−near.y, 5)（D）與 V1 控制器等價，需先能取用 Level 2 向量（見 §6 backlog）
A（簡單）e = xTarget − 320；steer = Kp·e + Kd·angle可回中位、加阻尼；e 仍含部分航向成分
C（最省事）以 angle 為主，用 length（前瞻）調增益並於曲率大時降速實作最快，貼線度最差

三個實機必做校正：(1) 中心常數 V2=320 / V1=160（座標系不同），鏡頭未裝正中央時需量一次 cx0；(2) 角度符號 官方定義「垂直線=0°、順時針為正」，鏡頭若鏡像/反裝會相反，務必先驗方向再調增益；(3) 增益起始值 Kp 小起步、加死區與限幅。

註：若改用「Cocoya 自訓循線模型」，模型本身即輸出兩點，可直接套用 V1 語意的 P+D 控制器（詳見 AI_Inference.html §4）。

6. 已知限制 / 待實機驗證

  • V1 曾有的 5 個錯誤已於 2026-09-19 修正（幀頭誤植 55 AA 55 AA、ADDR 誤植 0x00、checksum 未含幀頭、BLOCK ID 誤讀 1 byte、ARROW 欄位整組錯位）；修正依據為官方 HUSKYLENS Protocol.md、HuskyLensProtocolCore.c、HUSKYLENS.h。測試已加入官方範例幀與 checksum 拒收驗證。
  • V2 ARROW 的 length 偏移在協定文件為筆誤（標 offset 7），依官方 Result.cpp 的 union 佈局應為 offset 8；本模組依官方實作。
  • V2 checksum 公式官方文件未載明，係由 ProtocolV2.cpp 的 validateCheckSum（全幀和 mod 256）推得。
  • UART 讀取為「單次讀取 any() 可得位元組」，大幀若被分片需改為迴圈累積（I2C 固定讀 128 bytes）。
  • 本模組現以 arrows[ID] 儲存循線向量（同 ID 後者覆蓋）；官方 Python 範例為「有序清單 + level」，多級向量（Level 1/2）可能同 ID 而互相覆蓋 → 待實機確認後決定是否改為清單結構。
  • V1 官方協定其實有 演算法切換 0x2D / 學習 0x36 / 忘記 0x37 / 讀取名稱 0x2F，Cocoya 目前僅實作 V2；積木文案已改為「Cocoya 尚未實作」而非「V1 不支援」，以免誤導。
  • Tier 2（螢幕繪圖 draw_rect 0x26/draw_text/clear_text、拍照 take_photo 0x20、演算法參數 0x02/0x0E）與 Tier 3（多演算法 0x0C/0x0D、私有資料欄位）尚未實作，列 log/todo.md backlog。
  • docs/help/mcu_huskylens_*.html 尚未建立（現有 help 僅 AI 相關數塊）。
