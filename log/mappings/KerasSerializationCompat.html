Keras Serialization Compat（.keras 跨版本相容載入）

位置：resources/dataset_manager/_local_convert_tflite.py（Tauri / VSIX 雙模共用，隨 bundle.resources 打包進 Release） ｜首版：2026-09-04｜狀態：實機驗證通過（學生機 Release msi 遠端訓練 → 本地 TFLite 轉換成功）

解決的問題

遠端 Docker 訓練容器與本地 Python 環境的 TF/Keras 版本不一致，遠端產出的 .keras 內層 config 含本地 Keras 不認得的參數 → load_model 拋 Unrecognized keyword arguments，本地 TFLite 轉換失敗。

鐵律（2026-09-04 定案）：Keras 3 的 custom_objects 只對「未註冊/自訂類別」生效，無法覆寫內建類別（module: keras.layers）的反序列化行為；compile=False 也不影響 config 解析。跨版本相容問題必須走 config 預處理（本模組做法）或對齊兩端 TF 版本。

API

_sanitize_keras_config(keras_path) → str | None

  • 把 .keras（實為 zip：metadata.json / config.json / model.weights.h5）解開，對 config.json 遞迴剝除 _STRIP_KEYS 黑名單鍵後重打包成暫存檔。
  • 權重與其他 entry 原樣複製，對 tf.keras.models.load_model 完全透明。
  • 回傳暫存 .keras 路徑；無 config.json 或處理失敗回傳 None。

_load_model_compat(keras_path) → Model

四層 fallback：① 直接載入 → ② _sanitize_keras_config 預處理後重載（成功後清暫存）→ ③ custom_objects={'BatchNormalization': _CompatBatchNorm} → ④ 加 compile=False。②失敗時會自動從例外訊息 regex 解析並印出「下一個不相容層/參數 → 加入 _STRIP_KEYS」提示。

_STRIP_KEYS 維護指引

鍵所屬層剝除安全性
renorm / renorm_clipping / renorm_momentumBatchNormalizationrenorm=False 即預設語義，等價
synchronizedBatchNormalizationFalse 等價
quantization_configDense 等（Keras 3 新參數）None（未量化）等價
lora_rank / lora_name / lora_scaleDense 等（Keras 3 LoRA）None 等價

再冒新鍵的處理流程：跑遠端訓練 → 看 [LocalTFLite] 失敗訊息（已自動印出層名與參數）→ 把鍵名加入 _STRIP_KEYS → 重 build msi。若迭代超過兩輪仍有新鍵（兩端 Keras 差距過大），改走 SavedModel 方案：遠端 model.save(path, save_format='tf')、本地 tf.lite.TFLiteConverter.from_saved_model()（版本中立，跳過反序列化）。

量化鐵律：representative dataset 前處理必須與訓練一致（2026-09-04）

int8 精度崩壞根因：_local_convert_tflite.py 的 build_representative_dataset 曾直接餵 0~255 原始像素（缺訓練端 Rescaling(1./255)），converter 把 input scale 估錯 255 倍 → int8 輸出近乎隨機，且轉換流程不會報錯。f32 模型不吃 quantization 參數所以正常——症狀「int8 差、f32 正常」即此類問題。
  • 規則：representative 的所有前處理（Rescaling / preprocess_input / resize）必須與訓練 pipeline 逐項一致。
  • 驗證方式：同一批影像餵 int8 與 f32 比對 argmax 一致率（應 >95%）與 confidence 差（<0.1）；只看「檔案有產出」不夠。
  • 實測修復後（2026-09-04）：一致率 96.7%（58/60）、int8 準確率 81.7% vs f32 85.0%（正常損耗）。
