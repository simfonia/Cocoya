Cocoya Hardware Pin Map（開發板腳位 SSOT）

適用版本：2026-09-19。對應檔案：ui/src/modules/hardware/board_defs.js（資料）、 ui/src/modules/hardware/hardware_blocks.js（CocoyaBoard 解析器）、 ui/src/modules/hardware/hardware_generators.js（MicroPython 產生器）。

1. 資料結構（board_defs.js）

window.CocoyaBoardDefs.hardware.boards = {
  "<boardId>": {
    name:   "顯示名稱",                 // mcu_board_init 下拉文字、錯誤註解用
    vidPid: [["2E8A","0005"]],          // 序列埠自動偵測（需與 Rust / VSIX 表同步）
    pins: [                             // mcu_pin_shadow 下拉選項來源
      { ref: "board.GP8", label: "GP8 (M1A)", tags: ["digital","pwm"] }
    ],
    gpioMap: { GP8: 8 }                 // ref 的正規化鍵 → GPIO 號碼（權威映射）
  }
}
  • ref 是解析鍵（舊專案 XML 寫入的就是它）；label 只是下拉顯示文字，改 label 不影響舊專案。
  • tags 詞彙：digital / pwm / adc / input / i2c / uart / spi（目前尚未依積木類型過濾下拉，屬預留欄位）。
  • gpioMap 可含多個別名鍵（例：micro:bit 同時有 P0 與 pin0）。

2. 解析鏈（從積木到 GPIO 號碼）

mcu_pin_shadow 產生器        return [JSON.stringify(pin)]        // "board.GP8"
  ↓ Blockly 產生器管線（scrub_）→ 前置不可見標記：\u0001ID:x\u0002"board.GP8"
  ↓ generator.valueToCode('PIN')
cocoyaResolvePinNum()        → CocoyaBoard.resolveGpio(currentBoardId, ref)
  ↓ normalizePinRef()        剝除標記／引號／board. 前綴 → "GP8"
  ↓ gpioMap 查表（該板優先）→ 查無則掃描全部板兜底
  ↓ 命中 → pin_8 = machine.Pin(8, ...)；查無 → 「無法解析腳位」錯誤註解

鐵律：任何對 valueToCode() 結果做字串語意比對的產生器，都必須先剝除 \u0001ID:<blockId>\u0002（詳見 Framework_API_Index.html §7）。

5. 新增／修改開發板的檢查清單

  1. 在 board_defs.js 新增／更新條目：name / vidPid / pins / gpioMap。
  2. 不變式：每個 pins[].ref 都必須能在 gpioMap 命中（同一板內 ref 不得重複）。 直接跑測試驗證：cd ui; node --test "src/modules/hardware/*.test.mjs"（board_defs.test.mjs）。
  3. 動到 vidPid 時三處必須同步：board_defs.js、src-tauri/src/commands/mcu.rs（detect_board_id）、 src/handlers/serialOps.ts（boardIdMap）。
  4. 更新使用者說明文件：docs/help/hardware_pins_zh-hant.html 與 hardware_pins_en.html。
  5. 驗證：node --check、上述測試、npx vite build、實機（VSIX + Tauri）放 初始化開發板 後檢查腳位下拉與產生的 GPIO 號碼。
